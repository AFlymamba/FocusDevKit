# fxDevKit 使用说明

> 本文只讲怎么装、怎么用。
> 最后更新：2026-09-08
>
> 本轮更新要点：
> - §二 / §八 装全局 hooks 后**默认所有仓库都增强**，第 2 层 `install` 改为「重新启用」语义
> - §一 明确本地源码 `npm link` 方式（当前不发布 npm）
> - §九 新增 `fxdevkit logs` 命令

---

## 一、安装 CLI

当前 **不发布 npm**。用本地源码 `npm link` 方式：

```powershell
cd D:\products\devkit
npm install
npm run build
cd packages\cli
npm link
fxdevkit -v
```

能输出版本号（`@fxdevkit/cli 0.1.0`），说明 CLI 可用。

> ⚠️ 必须用 **系统自带的 npm**（PowerShell / cmd），不要用任何 IDE 托管的 Node。
> Windows 下 `npm link` 偶发清不干净，残留手动删 `~/.npm/@fxdevkit` 与 `~/.npm/fxdevkit.{cmd,ps1}`。

---

## 二、接管 git hooks（两层语义）

**第 1 层：装全局 hooks（只做一次，所有仓库默认都被增强）**

```bash
fxdevkit install --global
```

执行后 `git config --global core.hooksPath` 指向 fxdevkit 的 hook 目录，此后所有仓库（含以后新建、新克隆的）的提交、检出、推送都会先经过 dispatcher。

**装上全局 hooks 之后，所有仓库默认都被增强**——不再需要在每个仓库单独执行 `install`。只有想排除某个仓库时，才用下面的 `uninstall`。

**停用某个仓库**：

```bash
fxdevkit uninstall            # 在该仓库内：设 fxdevkit.enabled=false（停用）
fxdevkit install              # 重新启用（覆盖之前的停用标记）
```

**卸载全局 hooks**：

```bash
fxdevkit uninstall --global   # 所有仓库都不再被增强
```

> 仓库原本自带的 `.git/hooks/*`（如 husky / lefthook / 自定义脚本）**照常执行，不会被取缔**。fxdevkit 在它们之后追加增强。

---

## 三、安装插件

**插件由用户手动安装，fxdevkit 不代装。** 用 npm 安装即可，安装位置决定生效范围：

```bash
npm i -D @fxdevkit/plugin-commit-rules     仅当前仓库生效
npm i -g @fxdevkit/plugin-commit-rules     全局生效
```

内核在每次动作触发时扫描约定目录，装好即被发现，无需注册。

---

## 四、确认插件已被发现

```bash
fxdevkit plugin list
```

输出插件 id、版本、来源目录、声明的动作与权限。若某个插件未出现在列表中，说明它不在扫描目录内，或清单中的协议版本与内核不兼容。

查看单个插件的版本与命令：

```bash
fxdevkit commit -v        # 插件版本、来源目录、声明的命令
fxdevkit commit --help    # 该插件对外提供的命令
```

---

## 五、执行插件命令

插件可以自带命令，通过插件短名（`name`）路由执行：

```bash
fxdevkit <name> <command> [参数]
```

例如校验最近一次提交的信息是否合规：

```bash
fxdevkit commit check --sha HEAD
```

CLI 不内置任何插件命令，命令来自插件自身的声明。

---

## 六、配置

配置有两层来源（XDG-style）：

| 来源 | 位置 | 性质 |
|---|---|---|
| 源码默认 | `@fxdevkit/cli` 包内的 `DEFAULT_CONFIG` | npm 安装路径里，不可改、升级会被覆盖 |
| 用户覆盖 | `~/.fxdevkit/config.yaml` | 跟人走，跨升级保留 |

**工程目录零侵入**——fxdevkit 不在仓库根目录写任何配置文件（`<repo>/.fxdevkit.yaml` 不存在）。

加载优先级：**用户 > 源码默认**。数组整体替换，对象递归合并。

查看合并后的生效配置：

```bash
fxdevkit config show
```

校验插件配置是否合法：

```bash
fxdevkit config validate
```

### 6.1 限定插件作用目录（scope）

默认插件**全局生效**。若只想让某个插件在特定目录（及其子目录）下的仓库生效，在 `~/.fxdevkit/config.yaml` 里配 `projects`：

```yaml
plugins:
  commit-rules:
    enabled: true          # 不写 projects → 全局生效
  api-sync:
    enabled: true
    projects:
      - D:/products/order-service   # 只在该目录及子目录下的仓库生效
```

不在作用目录内的仓库会跳过该插件，`status` 会标「未生效」并给出原因，`doctor` 判定为通过（这是配置预期，不是故障）。

## 七、自检

hook 未挂载时，提交不会报错，只会静默地不增强。用 `doctor` 主动确认链路是否完整：

```bash
fxdevkit doctor
```

检查项包括：Node 与 Git 可用性、仓库识别、hooks 托管状态、入口路径有效性、插件加载结果。

---

## 八、最小闭环

1. `npm run build && cd packages\cli && npm link`（本地源码 link）
2. `fxdevkit install --global`（全局 hooks，做一次；之后所有仓库默认被增强）
3. `npm i -D @fxdevkit/plugin-commit-rules`（装第一个插件）
4. `fxdevkit plugin list` 确认已发现
5. `fxdevkit doctor` 确认链路正常
6. 正常提交，增强在背后发生

---

## 九、查看增强记录

**事件统计**：

```bash
fxdevkit report
```

**调度与执行日志**（新增，按天落盘到 `~/.fxdevkit/logs/YYYY-MM-DD.log`）：

```bash
fxdevkit logs                       # 今天全部
fxdevkit logs --core                # 只看内核调度日志
fxdevkit logs --plugin commit-rules # 只看某插件的执行日志
fxdevkit logs --level error         # 只看 error 及以上
fxdevkit logs --days                # 列出有哪些日期的日志文件
fxdevkit logs --last 20             # 只看最后 20 条
```

日志策略：warn / error 恒打到 stderr；info / debug 默认只落盘（避免每次 commit 刷屏）。设 `FXDEVKIT_DEBUG=1` 后全部实时打印。
