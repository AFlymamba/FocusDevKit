## 文档组织约定

| 文件 | 作用 |
|---|---|
| 本文件（`docs/插件列表.md`） | 插件总览索引：一眼看到有哪些插件、各自干什么、文档在哪 |
| `packages/<插件包>/README.md` | 某个插件的详细文档（工作原理、配置、使用），**跟着代码走** |

**加新插件时，两处都要更新**：这里加一行 + 新插件包里写 `README.md`。

## 如何查看已安装的插件

插件分两类：**项目内置**（`packages/plugin-*`）和**你 `npm i` 装的第三方插件**。两类都会被内核发现，用下面命令查看：

```bash
fxdevkit status                 # 当前仓库：插件加载状态、是否跳过、版本
fxdevkit plugin list            # 列出所有已发现的插件
```

## 附：为什么插件文档放在包目录下

- 插件是**独立可替换组件**，文档跟代码放一起，增删插件时文档自然随之走，不会出现"代码删了文档还在"。
- `docs/` 只保留**跨插件**的东西（本索引、概念词典、架构、修改指南），职责更清晰。
