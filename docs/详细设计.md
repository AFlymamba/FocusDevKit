## 0. 三种入口与代码落点

> 产品视角的三种入口见《架构设计》§1.1，本节只讲它们在代码层的落点。

| 入口 | 触发者 | 代码入口 | 状态 | 详述 |
|---|---|---|---|---|
| **自动触发** | git 动作 | `cli/src/index.ts` 的 `case 'hook'` → `kernel.dispatchHook()` | 已实现 | §4 |
| **主动触发** | 人敲命令 | `cli/src/index.ts` 的插件 name 路由 → `kernel.runPluginCommand()` | 已实现 | §5 |
| **对话触发** | AI 大脑 | 内核收集插件声明的 `skills`，供 AI 查询与调用 | 演进方向 | §5.4 |

内核在三条路径上做的是同一件事：

```
发现 → 装载 → 授权 → 派发 → 兜底
```

差异只在**触发者**和**结果回传方式**：

| 入口 | 结果怎么回 |
|---|---|
| 自动触发 | 写回文件或放行；只有插件显式 `reject` 才返回 1 |
| 主动触发 | 输出到终端，可返回非零退出码（给 CI 用） |
| 对话触发 | 结果回到对话 |

**内核不含领域语义**：以上三条路径都不假设任何具体领域（研发 / HR / 设计）。领域语义全在插件里，换目标只需换插件，内核一行不动。

## 2. Core 内部模块详解

core 由 **1 个调度器 + 10 个通用模块**组成。每个模块都是单一职责的小文件。

### 2.1 调度器（`kernel.ts`）

整个 Core 的入口只有两个函数：

| 函数 | 何时被调 | 做什么 |
|---|---|---|
| `dispatchHook(hookName, args)` | git 触发 hook 路径时 | 走第 4 节描述的全流程 |
| `runPluginCommand(pluginId, command, args)` | 用户敲 `fxdevkit run` 时 | 走第 5 节描述的全流程 |

两者**共用**：插件发现、装载、授权、ctx 构造、结果收集。
两者**唯一差异**：命令路径额外触发事件订阅分发。

### 2.2 通用模块（10 个）

#### ① 路径（`paths.ts`）

```ts
paths = {
  home: FXDEVKIT_HOME,                    // ~/.fxdevkit
  hooks: path.join(home, 'hooks'),         // 全局 hooks 安装产物
  events: path.join(home, 'events'),       // 事件落盘（按月）
  cache: path.join(home, 'cache'),
  plugins: path.join(home, 'plugins'),     // 全局级插件安装位置
  mockServer: path.join(home, 'mock-server'),
  logs: path.join(home, 'logs'),           // 日志落盘（按天）
  userConfig: path.join(home, 'config.yaml'),
  devices: path.join(home, 'device.json'),
}
```

任何子目录都有 `ensureDir` 兜底，**删了不会破坏系统**。

#### ② git 信息采集（`git.ts`）

```ts
detectGitContext(cwd): GitContext = {
  root,           // git 仓库根目录
  branch,         // 当前分支
  isMerge,        // 是不是 merge 提交
  isRebase,       // 是不是 rebase 中
  isAmend,        // 是不是 amend
  remoteUrl,      // 远程地址
  ...
}
```

**只读**——不在这里写任何东西。改文件/改提交信息是插件 + `fs:repo` 权限的事。

#### ③ 配置（`config.ts`）

```ts
loadConfig(): {
  config: FxDevkitConfig,           // 合并后的总配置
  sources: ConfigSource[],          // 各来源（给 doctor 用）
}
```

合并规则：**用户配置覆盖源码默认**（`{...DEFAULT_CONFIG, ...userConfig}`，用户优先）。工程目录零侵入——`loadConfig` 不接收 `repoRoot`，不读 `<repo>/.fxdevkit.yaml`。

```ts
pluginConfig<T>(config, pluginId, validate?): T
  // 从 config 里抽 <pluginId> 子树，可选 validateConfig 归一化
```

#### ④ 事件（`events.ts`）

```ts
createEmitter(pluginId, ctx): Emitter
  // 返回 ctx.emit。事件落到 ~/.fxdevkit/events/YYYY-MM.jsonl

readEvents({ month?, pluginId?, type? }): EventRecord[]
  // 读历史事件（CLI 的 report 命令用）

dispatchSubscriptions(plugins, event, ctx): void
  // **只在命令路径调**，hook 路径不触发（避免拖慢提交）
```

#### ⑤ 日志（`logger.ts`）

```ts
createCoreLogger(verbose?): Logger
createPluginLogger(pluginId, verbose?): Logger
readLogs({ day?, channel?, pluginId?, level?, last? }): LogRecord[]
listLogDays(): string[]
```

**双通道**：
- `core` 通道：内核调度日志（"派发 hook"、"候选插件 N 个"、"执行/完成"）
- `plugin` 通道：插件通过 `ctx.logger` 输出的日志

**打印策略**：

| 级别 | hook 路径 | 命令路径 | 落盘 |
|---|---|---|---|
| `error` | stderr | stderr | ✅ |
| `warn` | stderr | stderr | ✅ |
| `info` | 只落盘 | stderr + 落盘（verbose） | ✅ |
| `debug` | 只落盘（需 `FXDEVKIT_DEBUG=1`） | 同上 | ✅ |

**控制变量**：`FXDEVKIT_DEBUG=1`、`FXDEVKIT_LOG_LEVEL`、`FXDEVKIT_LOG=0`。

#### ⑥ 作用域（`scope.ts`）

```ts
isPluginInScope(config, pluginId, repoRoot): boolean
  // plugins.<id>.projects 不存在/为空 → true（全局生效）
  // 否则 → repoRoot 必须以某元素为前缀（Windows 不区分大小写）
```

**插件无感**——`ctx.scope` 这个字段不存在；过滤在 core 这层做。

#### ⑦ hooks 安装（`hooks.ts`）

```ts
installHooks(cwd, nodePath, cliEntry, { global }): void
  // 生成 ~/.fxdevkit/hooks/<hook-name> 脚本
  // global=true: git config --global core.hooksPath（装一次，所有仓库默认增强）

uninstallHooks({ global }): void
  // 删全局 hooks 目录 / 当前仓库设 fxdevkit.enabled=false（显式停用）

isRepoEnabled(repoRoot): boolean
  // 默认启用——除非显式设 fxdevkit.enabled=false 停用

enableRepo(repoRoot): void
  // 显式启用（覆盖之前的 false 停用标记；全局未装时自动补装）
```

**关键函数细节**：
- `runRepoOwnHook(repoRoot, hookName, args)`：仓库自有 hook 优先（保留 husky / lefthook 装的）
- `resolveRunner(scriptPath)`：按 shebang 解析解释器（Windows 下不直接 spawn 带 `#!/bin/sh` 脚本）

#### ⑧ 插件管理（`plugins.ts`）

```ts
discoverPlugins(repoRoot?): Discovered[]
  // 扫以下位置找 plugin-* / fxdevkit-plugin-*：
  //   <repo>/node_modules
  //   ~/.fxdevkit/plugins
  //   ~/.fxdevkit/node_modules
  //   $FXDEVKIT_PLUGIN_PATHS 环境变量
  // 同一 id 多个版本 → 取最高版本（其余丢弃并记档）

loadPlugin(discovered): PluginDefinition
  // 动态 import + 默认导出检查
  // id 不一致 → 抛错

selectPlugins(discoveredList, hookName): PluginDefinition[]
  // 按 manifest.hooks 字段过滤 + 启用判断
```

#### ⑨ server（`server.ts`）

```ts
createServerClient(config): ServerClient
  // 连真实 server（FXDEVKIT_SERVER_URL）

createDeniedServer(pluginId, logger): ServerClient
  // 拒绝客户端（无 net:server 权限时给插件）

createMockServer(): MockServerHandle
  // 启动本地 mock（默认 FXDEVKIT_SERVER_MOCK=1）
```

**默认 mock**——系统默认不联网，必须显式关掉才连真服务。

#### ⑩ 入口导出（`index.ts`）

纯 re-export。改导出名 = 破坏兼容。

## 3. SDK 详细 API

`packages/sdk/src/index.ts` 提供的所有公共类型与方法。

### 3.1 入口

```ts
// 插件作者用
definePlugin<ConfigType>(definition: PluginDefinition<ConfigType>): PluginDefinition<ConfigType>

// 校验工具
validateConfig<T>(raw: unknown, schema: ConfigSchema<T>): T
```

### 3.2 类型清单

```ts
type PluginId = string

interface PluginManifest {
  id: PluginId
  version: string
  apiVersion: '1'
  hooks?: HookName[]                    // 订阅哪些 git hooks
  commands?: string[]                   // 暴露哪些命令
  permissions?: Permission[]            // 能力声明
  subscriptions?: Subscription[]        // 事件订阅（仅命令路径生效）
  defaultConfig?: unknown
}

type Permission =
  | 'fs:repo'                            // 仓库内文件读写
  | 'fs:read'                            // 只读
  | 'events:write'                       // 发事件
  | 'net:server'                         // 访问外部服务
  | 'git:write'                          // git 写操作（amend、rebase 等）

interface HookContext<T = unknown> {
  pluginId: PluginId
  config: T
  logger: Logger
  git: GitContext
  args: string[]
  messageFile?: string                  // commit-msg 时存在
  emit: Emitter                         // 无 events:write 时是空函数
  server: ServerClient                  // 无 net:server 时是拒绝客户端
  permissions: ReadonlySet<Permission>
}

interface CommandContext<T = unknown> extends HookContext<T> {
  command: string
  cwd: string
}

type HandlerResult = 'accept' | 'modify' | 'reject'
  // accept: 放过
  // modify: 已改写（如 messageFile），Core 不再处理
  // reject: 阻断
```

### 3.3 SDK 的边界（什么不做）

| 不做 | 原因 |
|---|---|
| ❌ 不发网络请求 | 这是 server.ts 的事 |
| ❌ 不读/写文件 | 这是插件 + ctx 的事 |
| ❌ 不 spawn 子进程 | 这是插件 + ctx 的事 |
| ❌ 不替插件注入 ctx 字段 | 注入是 kernel 在 dispatch 时做的 |
| ✅ 只提供 | 类型 + `definePlugin` + `validateConfig` 工具 |

## 4. 数据流：一次 git commit（hook 路径）

### 4.1 全流程（12 阶段）

| 阶段 | 执行者 | 做了什么 | 代码位置 |
|---|---|---|---|
| ① | git | 读 `core.hooksPath` → 找到 commit-msg hook 脚本 | git 内部 |
| ② | dispatcher 脚本 | 直接调 CLI 的 `hook` 子命令，参数透传 | 全局 hooks 安装产物 |
| ③ | CLI | 解析到 `case 'hook'` → `kernel.dispatchHook('commit-msg', [msgFile])` | `cli/src/index.ts` |
| ④ | Core | 读配置 / 找仓库根 / 判定是否被显式停用 | `core/src/kernel.ts` `dispatchHook` |
| ⑤ | Core | 仓库自有 hook 优先：`runRepoOwnHook`（保留 husky / lefthook 装的） | `core/src/hooks.ts` |
| ⑥ | Core | scope 过滤 → 选出候选插件 | `core/src/scope.ts` |
| ⑦ | Core | 对每个候选：`loadPlugin`（动态 `import()`） | `core/src/plugins.ts` |
| ⑧ | Core | 三层授权 + 构造 ctx | `core/src/kernel.ts` |
| ⑨ | Plugin | handler 被调用，`fs.writeFileSync(ctx.messageFile, ...)` | `plugin-commit-rules/src/index.ts` |
| ⑩ | Core | 收集所有插件结果；任一 reject → 返回 1 | `core/src/kernel.ts` |
| ⑪ | CLI | 返回 exit code 给 dispatcher | - |
| ⑫ | git | exit=0 用改写后的信息完成提交；非 0 中止 | git 内部 |

### 4.2 阶段 ② 详解：dispatcher 脚本

全局 hooks 安装时，core 在 `~/.fxdevkit/hooks/` 下生成每个 hook 名对应的 shim：

```sh
# ~/.fxdevkit/hooks/commit-msg
exec <cli-entry> hook commit-msg "$@"
```

git 设置 `core.hooksPath` 指向该目录，所有仓库的 `commit-msg` 都先到这里。

### 4.3 阶段 ④ 详解：仓库停用判定

装全局 hooks 后，所有仓库**默认都被增强**。唯一例外是显式停用的仓库：

- **全局 hooks**（`git config --global core.hooksPath`）：dispatcher 装上没
- **停用标记**（`.git/config` 的 `fxdevkit.enabled=false`）：当前仓库是否被显式停用

`isRepoEnabled` 只在 `fxdevkit.enabled=false` 时返回 false；键不存在（默认）即启用。
目录收窄优先用插件的 `projects` 作用域（见 4.4），只有个别仓库才需要 `fxdevkit uninstall`。

### 4.4 阶段 ⑥ 详解：scope 过滤

```ts
// core/src/scope.ts
function isPluginInScope(config, pluginId, repoRoot) {
  const projects = config.plugins?.[pluginId]?.projects
  if (!projects || projects.length === 0) return true   // 不配 = 全局
  return projects.some(p =>
    repoRoot.toLowerCase().startsWith(p.toLowerCase())   // 前缀匹配
  )
}
```

### 4.5 阶段 ⑧ 详解：ctx 构造

每个字段按权限**逐个注入**，没声明的权限 → 给空实现，**不报错**：

```ts
const ctx: HookContext = {
  pluginId,
  config: pluginConfigValue,
  logger: createPluginLogger(pluginId),  // 走 plugin 通道
  git: detectGitContext(repoRoot),
  args,
  messageFile: hookName === 'commit-msg' ? args[0] : undefined,
  emit: permissions.has('events:write')
    ? createEmitter(pluginId, ctx)
    : createSilentEmitter(),
  server: permissions.has('net:server')
    ? createServerClient(config.server)
    : createDeniedServer(pluginId, logger),
  permissions,
}
```

### 4.6 阶段 ⑩ 详解：结果收集

```ts
for (const plugin of candidates) {
  const result = await plugin.hooks[hookName](ctx)
  switch (result) {
    case 'accept': break
    case 'modify': break                  // Core 不再二次处理
    case 'reject': rejected = true; break
  }
}
return rejected ? 1 : 0                   // 给 git 用
```

### 4.7 这一路上我能看到什么

| 行为 | 是否可见 |
|---|---|
| 正常 commit（无 reject） | 终端**完全静默** |
| 插件 reject | stderr 看到 plugin 输出的诊断，git commit 中止 |
| 插件 modify（如加前缀） | 终端**完全静默**，但 message 已被改 |
| 日志落盘 | `~/.fxdevkit/logs/YYYY-MM-DD.log` 有 JSON 行 |
| 全程可追溯 | `fxdevkit logs --core --last 50` |

设计取舍：终端静默是为了不打扰提交；想实时看就 `FXDEVKIT_DEBUG=1`。

## 5. 数据流：一次 fxdevkit run（命令路径）

### 5.1 全流程

| 阶段 | 执行者 | 做了什么 |
|---|---|---|
| ① | CLI | 解析到 `case 'run'` → 取 `pluginId` + `command` + `args` |
| ② | CLI | `kernel.runPluginCommand(pluginId, command, args)` |
| ③ | Core | 与 hook 路径共用：`discoverPlugins` → `loadPlugin` → 三层授权 → 构造 `CommandContext` |
| ④ | Core | **额外步骤**：触发事件订阅分发（hook 路径不做这一步） |
| ⑤ | Plugin | handler 执行；ctx 类型是 `CommandContext` |
| ⑥ | Core | 收集结果并打印 |

### 5.2 与 hook 路径的差异

| 维度 | hook 路径 | 命令路径 |
|---|---|---|
| 触发源 | git 调 hook 脚本 | 用户直接敲 CLI |
| 入口分支 | `case 'hook'` | `case 'run'` |
| ctx 类型 | `HookContext` | `CommandContext` |
| 仓库 hook 处理 | 跑 `runRepoOwnHook` | 不跑 |
| **订阅分发** | **关闭** | **开启** |
| 日志策略 | info 只落盘不打印 | info 实时打印 + 落盘（verbose 模式） |
| 退出码语义 | 给 git 用（0 = 放行，非 0 = 阻断） | 给用户看（0 = 成功） |

### 5.3 共用部分

`discoverPlugins` / `loadPlugin` / 三层授权 / ctx 构造 —— **完全一致**。

### 5.4 第三种入口：对话触发（演进方向）

前两条路径今天就能用。第三种是**对话触发**——人在飞书 @ 机器人说一句话，AI 去调插件提供的 skill 和 MCP。

**当前状态：不实现，但契约位置留着。** 插件清单里三类契约并列：

```ts
interface PluginManifest {
  hooks?: HookName[]        // 自动触发：声明订阅哪些动作
  commands?: string[]       // 主动触发：声明提供哪些命令
  skills?: SkillDef[]       // 对话触发：声明给 AI 用哪些能力（将来）
}
```

落到代码上只有两点：

| 项 | 说明 |
|---|---|
| **清单字段** | `skills` 与 `hooks` / `commands` 并列，加字段即可，不用改内核结构 |
| **内核职责** | 只负责**收集**各插件声明的 skill 并暴露给 AI 查询与调用，**不实现任何一个 skill** |

这跟「内核不实现任何业务能力」是同一条原则——skill 是插件的私事，跟 hook、command 一样。将来接 AI 大脑时，内核多一个收集口，不改现有调度逻辑。

---

## 6. 插件生命周期四阶段

| 阶段 | 在 Core 哪里 | 输入 | 输出 |
|---|---|---|---|
| **发现** | `plugins.ts` 的 `discoverPlugins` | `repoRoot`（可选） | `Discovered[]` 列表 |
| **装载** | `plugins.ts` 的 `loadPlugin` | 单个 `Discovered` | `PluginDefinition` 或抛错 |
| **授权** | `kernel.ts` 内联 | manifest + 用户配置 + ctx 字段需求 | 构造完成的 `ctx` |
| **派发** | `kernel.ts` 的 `dispatchHook` / `runPluginCommand` | `ctx` + hook/command 名 | handler 执行结果 |

任何阶段失败**不阻断 git**，只是跳过该插件或该步骤并打日志。

---

## 7. 三层授权机制

| 层 | 检查 | 失败行为 |
|---|---|---|
| **身份识别** | manifest.id === definition.id | 丢弃该插件 |
| **能力识别** | `permissions` 列表里声明了什么，ctx 才给什么 | 没声明 → 给空实现，**不报错** |
| **边界识别** | `ctx.config` 只注入插件自己的 `config` 字段 | 不可能越界读别人配置 |

**为什么给空实现而非报错**：让插件可以**优雅降级**——比如没声明 `net:server` 时，`ctx.server` 是拒绝客户端而不是抛错，插件代码可以走"没权限就不联网"的分支。

## 8. 横切能力

### 8.1 配置

```
@fxdevkit/cli 包内 DEFAULT_CONFIG    # 源码默认（npm 安装路径里，不可改、升级会被覆盖）
~/.fxdevkit/config.yaml             # 用户自定义（跟人走，跨升级保留）
合并规则：用户自定义覆盖源码默认（用户优先）
工程目录零侵入：<repo>/.fxdevkit.yaml 不存在
```

### 8.2 事件

```
落盘：~/.fxdevkit/events/YYYY-MM.jsonl（JSON Lines）
订阅：plugin manifest 的 subscriptions 数组
约束：只在命令路径分发，hook 路径不触发
```

### 8.3 日志

```
双通道：core / plugin
落盘：~/.fxdevkit/logs/YYYY-MM-DD.log
打印策略：warn/error 恒打 stderr；info/debug 默认只落盘
控制：FXDEVKIT_DEBUG=1 / FXDEVKIT_LOG_LEVEL / FXDEVKIT_LOG=0
```

### 8.4 作用域

```
字段：plugins.<id>.projects: string[]
判定：内核做，插件无感
规则：缺失/空 → 全局；否则前缀匹配（Windows 不区分大小写）
```

### 8.5 全局目录

```
~/.fxdevkit/
├── config.yaml                  # 主配置
├── logs/YYYY-MM-DD.log          # 日志（按天）
├── events/YYYY-MM.jsonl         # 事件（按月）
├── hooks/<hook-name>            # 全局 hooks 安装产物
├── plugins/                     # 全局级插件
├── cache/                       # 缓存
├── mock-server/                 # mock server 状态
└── device.json                  # 设备标识
```

任何一项都**可重建**，没有不可逆的隐藏状态。

## 9. 我能改什么（可控清单）

> 每一层都标出：**能改什么**、**怎么验证**、**坏了会怎样**。

### 9.1 改 Core（影响所有插件）

| 改动类型 | 验证方法 | 风险 |
|---|---|---|
| 改 `kernel.ts` 调度流程 | `npm run build -w @fxdevkit/core && fxdevkit doctor && fxdevkit hook commit-msg <msg-file>` | 🔴 高 |
| 改 `plugins.ts` 发现规则 | `fxdevkit plugins`（查看列表） | 🔴 高 |
| 改 `hooks.ts` git config 策略 | 装/卸各跑一次，再 `git config --global core.hooksPath` 检查 | 🟡 中 |
| 改 `events.ts` 落盘格式 | 触发一次命令路径，看 `~/.fxdevkit/events/*.jsonl` | 🟢 低 |
| 改 `logger.ts` 输出格式 | `fxdevkit logs --last 1` | 🟢 低 |
| 改 `scope.ts` 匹配规则 | 配/不配 `projects` 各跑一次 | 🟡 中 |

### 9.2 改 SDK（影响所有插件编译）

| 改动类型 | 验证方法 | 风险 |
|---|---|---|
| 加新类型 | `npm run build` | 🟢 低 |
| 改 `HookContext` / `CommandContext` schema | `npm run build`，所有插件跟着编译 | 🔴 高 |
| 改 `definePlugin` 签名 | 同上 | 🔴 高 |
| 改 `validateConfig` 默认行为 | 单独写测试 | 🟡 中 |

### 9.3 增/删/改一个插件

```bash
# 新增
mkdir -p packages/plugin-<name>
# 写 package.json（含 fxdevkit 字段）+ src/index.ts（definePlugin）
npm run build -w @fxdevkit/plugin-<name>
npm link                                     # 全局生效（同机）
fxdevkit plugins | grep <name>                # 验证

# 删除
rm -rf packages/plugin-<name>                 # Core 下次扫描就看不到了

# 改
# 改 src 后：
npm run build -w @fxdevkit/plugin-<name>      # build 后全局命令立即生效（npm link）
```

### 9.4 改配置

| 改什么 | 何时生效 | 验证 |
|---|---|---|
| `~/.fxdevkit/config.yaml` | 下次命令/hook 运行时 | `fxdevkit doctor` |
| 仓库停用状态（`fxdevkit.enabled=false`） | 下次 hook 触发时 | `fxdevkit status` |

### 9.5 改全局状态（`~/.fxdevkit/*`）

| 路径 | 改了会发生什么 |
|---|---|
| `logs/` | 删了下次重新生成，不影响运行 |
| `events/` | 删了下次重新生成，不影响运行 |
| `hooks/` | 删了 = 全局 hooks 失效（git 用回默认） |
| `plugins/` | 删了 = 全局插件找不到 |
| `config.yaml` | 改了 = 下次运行生效 |
| `mock-server/` | 删了 = 下次再启 mock 时重建 |

**底线**：所有全局状态都是**可重建**的。

## 10. 失败模型与兜底

### 10.1 调度层失败处理

| 阶段 | 失败 | 行为 |
|---|---|---|
| 发现 | 找不到插件 | 不派发 |
| 装载 | import 抛错 | 跳过该插件，记日志 |
| 授权 | id 不一致 / 配置非法 | 丢弃，记日志 |
| 派发 | handler 抛错 / 超时 | 记 reject 日志，按 reject 处理 |
| 收集 | 异常累加 | 一票否决 → 阻断 git |

### 10.2 全局状态可重建

- 所有 `~/.fxdevkit/*` 子目录都是 `ensureDir` 兜底
- `fxdevkit uninstall --global` 是可逆操作（git config 可还原）
- 唯一不可逆的：把全局 hooks 指向别处覆盖了——但 `fxdevkit doctor` 会告警

### 10.3 故障定位路径

```
问题？→  fxdevkit doctor                          # 健康总览
      →  fxdevkit logs --core --last 50            # 内核调度日志
      →  fxdevkit logs --plugin <id>               # 某插件的日志
      →  fxdevkit status                           # 当前仓库状态
      →  ~/.fxdevkit/logs/YYYY-MM-DD.log           # 直接看文件
```
