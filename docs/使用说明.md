# fxDevKit 使用说明

> 本文只讲怎么装、怎么用。
> 最后更新：2026-09-04

---

## 一、安装 CLI

```bash
npm install -g @fxdevkit/cli
fxdevkit -v
```

能输出版本号，说明 CLI 可用。

---

## 二、接管 git hooks（分两层）

增强发生在研发动作背后，需要先让 fxdevkit 接住这些动作。接管分**两层开关**，缺一不可：

**第 1 层：装全局 hooks（只做一次）**

```bash
fxdevkit install --global
```

执行后 `git config --global core.hooksPath` 指向 fxdevkit 的 hook 目录，此后所有仓库（含以后新建、新克隆的）的提交、检出、推送都会先经过 dispatcher。

**第 2 层：在要增强的仓库里启用**

```bash
cd <你的仓库>
fxdevkit install
```

执行后该仓库的 `fxdevkit.enabled` 置为 `true`，才开始被插件增强。

> **为什么分两层**：装全局 hooks ≠ 每个仓库都被增强。第 1 层保证"都能接住"，第 2 层决定"哪个真的增强"，避免新克隆的仓库一上来就被改写提交信息。

**取消**：

```bash
fxdevkit uninstall            # 停用当前仓库（全局 hooks 保留，其他仓库不受影响）
fxdevkit uninstall --global   # 卸载全局 hooks，所有仓库都不再被增强
```

> 仓库原本自带的 `.git/hooks/*`（如 husky / lefthook / 自定义脚本）**照常执行，不会被取缔**。fxdevkit 在它们之后追加增强。

---

## 三、安装插件

**插件由用户手动安装，fxdevkit 不代装。** 用 npm 安装即可，安装位置决定生效范围：

```bash
npm i -D @fxdevkit/plugin-commit-rules     仅当前仓库生效
npm i -g @fxdevkit/plugin-commit-rules     全局生效
```

内核在每次动作触发时扫描约定目录，装好即被发现，无需注册。

---

## 四、确认插件已被发现

```bash
fxdevkit plugin list
```

输出插件 id、版本、来源目录、声明的动作与权限。若某个插件未出现在列表中，说明它不在扫描目录内，或清单中的协议版本与内核不兼容。

查看单个插件的版本与命令：

```bash
fxdevkit commit -v        # 插件版本、来源目录、声明的命令
fxdevkit commit --help    # 该插件对外提供的命令
```

---

## 五、执行插件命令

插件可以自带命令，通过插件短名（`name`）路由执行：

```bash
fxdevkit <name> <command> [参数]
```

例如校验最近一次提交的信息是否合规：

```bash
fxdevkit commit check --sha HEAD
```

CLI 不内置任何插件命令，命令来自插件自身的声明。

---

## 六、配置

配置分两层，职责不重叠：

| 位置 | 归属 | 放什么 |
|---|---|---|
| `~/.fxdevkit/config.yaml` | 内核 | hook 行为、Server 连接、事件记录开关 |
| `<仓库>/.fxdevkit.yaml` | 项目 | 该项目特有的增强规则 |

查看合并后的生效配置：

```bash
fxdevkit config show
```

校验插件配置是否合法：

```bash
fxdevkit config validate
```

### 6.1 限定插件作用目录（scope）

默认插件**全局生效**。若只想让某个插件在特定目录（及其子目录）下的仓库生效，在 `~/.fxdevkit/config.yaml` 里配 `projects`：

```yaml
plugins:
  commit-rules:
    enabled: true          # 不写 projects → 全局生效
  api-sync:
    enabled: true
    projects:
      - D:/products/order-service   # 只在该目录及子目录下的仓库生效
```

不在作用目录内的仓库会跳过该插件，`status` 会标「未生效」并给出原因，`doctor` 判定为通过（这是配置预期，不是故障）。

## 七、自检

hook 未挂载时，提交不会报错，只会静默地不增强。用 `doctor` 主动确认链路是否完整：

```bash
fxdevkit doctor
```

检查项包括：Node 与 Git 可用性、仓库识别、hooks 托管状态、入口路径有效性、插件加载结果。

---

## 八、最小闭环

1. `npm install -g @fxdevkit/cli`
2. `fxdevkit install --global`（全局 hooks，做一次）
3. 进入仓库执行 `fxdevkit install`（启用本仓库增强）
4. `npm i -D @fxdevkit/plugin-commit-rules`
5. `fxdevkit plugin list` 确认已发现
6. `fxdevkit doctor` 确认链路正常
7. 正常提交，增强在背后发生

---

## 九、查看增强记录

增强行为会记录在本地事件文件中：

```bash
fxdevkit report
```
