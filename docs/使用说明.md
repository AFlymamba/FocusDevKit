# fxDevKit 使用说明

> 本文只讲怎么装、怎么用。
> 最后更新：2026-09-04

---

## 一、安装 CLI

```bash
npm install -g @fxdevkit/cli
fxdevkit -v
```

能输出版本号，说明 CLI 可用。

---

## 二、托管 git hooks

增强发生在研发动作背后，因此需要先让 fxdevkit 接住这些动作。在目标仓库中执行：

```bash
cd <你的仓库>
fxdevkit install
```

执行后 git 的 `core.hooksPath` 会指向 fxdevkit 的 hook 目录，此后提交、检出、推送等动作会先经过内核。

取消托管：

```bash
fxdevkit uninstall
```

---

## 三、安装插件

**插件由用户手动安装，fxdevkit 不代装。** 用 npm 安装即可，安装位置决定生效范围：

```bash
npm i -D @fxdevkit/plugin-commit-rules     仅当前仓库生效
npm i -g @fxdevkit/plugin-commit-rules     全局生效
```

内核在每次动作触发时扫描约定目录，装好即被发现，无需注册。

---

## 四、确认插件已被发现

```bash
fxdevkit plugin list
```

输出插件 id、版本、来源目录、声明的动作与权限。若某个插件未出现在列表中，说明它不在扫描目录内，或清单中的协议版本与内核不兼容。

查看单个插件的版本与命令：

```bash
fxdevkit commit -v        # 插件版本、来源目录、声明的命令
fxdevkit commit --help    # 该插件对外提供的命令
```

---

## 五、执行插件命令

插件可以自带命令，通过插件短名（`name`）路由执行：

```bash
fxdevkit <name> <command> [参数]
```

例如校验最近一次提交的信息是否合规：

```bash
fxdevkit commit check --sha HEAD
```

CLI 不内置任何插件命令，命令来自插件自身的声明。

---

## 六、配置

配置分两层，职责不重叠：

| 位置 | 归属 | 放什么 |
|---|---|---|
| `~/.fxdevkit/config.yaml` | 内核 | hook 行为、Server 连接、事件记录开关 |
| `<仓库>/.fxdevkit.yaml` | 项目 | 该项目特有的增强规则 |

查看合并后的生效配置：

```bash
fxdevkit config show
```

校验插件配置是否合法：

```bash
fxdevkit config validate
```

---

## 七、自检

hook 未挂载时，提交不会报错，只会静默地不增强。用 `doctor` 主动确认链路是否完整：

```bash
fxdevkit doctor
```

检查项包括：Node 与 Git 可用性、仓库识别、hooks 托管状态、入口路径有效性、插件加载结果。

---

## 八、最小闭环

1. `npm install -g @fxdevkit/cli`
2. 进入仓库执行 `fxdevkit install`
3. `npm i -D @fxdevkit/plugin-commit-rules`
4. `fxdevkit plugin list` 确认已发现
5. `fxdevkit doctor` 确认链路正常
6. 正常提交，增强在背后发生

---

## 九、查看增强记录

增强行为会记录在本地事件文件中：

```bash
fxdevkit report
```
