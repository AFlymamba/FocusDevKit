# fxdevkit 命令手册

> fxDevKit（fxdevkit）— 研发动作背后的插件化增强层。
>   
> 本文档基于当前已实现命令（`@fxdevkit/cli` 1.0.0）逐条整理，命令示例来自真实终端输出。



---

## 零、安装（本地源码方式，不发布 npm）

> fxdevkit 目前**不发布到 npm registry**。用 `npm link` 把源码里的 CLI 链接到全局，本地直接使用，改代码即生效。

### 一次性安装

在你的终端（PowerShell 或 cmd，**注意是系统自带的 npm，不是任何 IDE 托管的 Node**）里执行：

```powershell
cd D:\products\devkit
npm install        # 首次安装依赖（依赖变化时重跑）
npm run build      # 编译所有包，生成 dist
cd packages\cli
npm link           # 把 @fxdevkit/cli 链接到全局，注册 fxdevkit 命令
```

验证：

```powershell
fxdevkit --version
# @fxdevkit/cli 1.0.0
```

### 日常开发循环（改了源码怎么生效）

`npm link` 指向的是源码目录，所以**不需要重复 link**。改了 `packages/*/src` 里的代码后：

```powershell
cd D:\products\devkit
npm run build      # 重新编译，dist 更新后命令立即生效
```

只有改了 `packages/cli/package.json` 的 `bin` 或依赖时，才需要重新 `npm link`。

### 卸载

```powershell
npm uninstall -g @fxdevkit/cli
```

> 若 Windows 下残留（`npm link` 偶发清不掉符号链接），手动删：
>   
> `%APPDATA%\npm\node_modules\@fxdevkit` 目录，以及 `%APPDATA%\npm\fxdevkit`、`fxdevkit.cmd`、`fxdevkit.ps1` 三个 shim 文件。

## 二、命令总览

| 命令                                 | 作用                                                    |
| ---------------------------------- | ----------------------------------------------------- |
| `fxdevkit status`                  | 查看当前状态：fxdevkit 版本、当前仓库、hooks 托管情况、插件及版本              |
| `fxdevkit doctor`                  | 检查增强链路是否正常（Node / Git / 仓库 / hooks / 插件加载）            |
| `fxdevkit install`                 | 挂载全局 hooks（一次）：所有仓库（含以后新建的）都会走 dispatcher，且**默认全部增强** |
| `fxdevkit uninstall`               | 卸载全局 hooks，所有仓库均不再增强                                  |
| `fxdevkit disable`                 | 停用**当前目录**的增强（写进用户配置的 exclude，含其所有子目录）                |
| `fxdevkit enable`                  | 恢复**当前目录**的增强（从 exclude 中移除）                          |
| `fxdevkit update [version]`        | 更新 fxdevkit（不带版本=最新，带版本=回退到指定版本）                    |
| `fxdevkit plugin list`             | 列出插件及版本、hooks、permissions                             |
| `fxdevkit plugin add <pkg>`        | 安装插件（`npm install` 到用户目录）                             |
| `fxdevkit plugin remove <pkg>`     | 移除插件                                                  |
| `fxdevkit plugin enable <id>`      | 启用插件                                                  |
| `fxdevkit plugin disable <id>`     | 停用插件                                                  |
| `fxdevkit config show`             | 打印合并后的生效配置（含各层来源）                                     |
| `fxdevkit config validate`         | 校验各插件配置是否合法                                           |
| `fxdevkit report`                  | 统计本地事件记录（顶部带增强状态概览）                                 |
| `fxdevkit trace`                   | 回溯增强：最近一次生效 / 跳过 / 开关变更                             |
| `fxdevkit logs`                    | 查看日志（core / plugin 双通道，支持按插件、级别、日期过滤）                 |
| `fxdevkit <name> <cmd>`            | 执行插件命令（按插件短名路由），如 `fxdevkit feishu serve`                |
| `fxdevkit help`                    | 显示本帮助                                                 |

**参数简写速查**

| 简写 | 全写 | 适用 |
|---|---|---|
| `-v` | `--version` | fxdevkit 自身 / 插件（`fxdevkit <plugin> -v`） |
| `-h` | `--help` / `help` | fxdevkit 自身 / 插件（`fxdevkit <plugin> -h`） |
| `-n` | `--last` | logs、trace |

> `fxdevkit <name> <cmd>` 是插件命令的通用路由，`name` 来自插件清单，**CLI 不认识任何具体插件**。
> 某个插件有哪些子命令，看 `fxdevkit <name> -h`；详细用法看 [`插件列表.md`](插件列表.md) 里对应的插件文档。

## 三、核心命令详解

### `fxdevkit status`

查看当前状态：版本、当前仓库、hooks 是否托管、插件列表。

```bash
$ fxdevkit status
[fxdevkit] @fxdevkit/cli 1.0.0 · Node v22.22.2
[fxdevkit] 仓库 D:/products/devkit
[fxdevkit] hooks 已托管
[fxdevkit] 插件:
  commit        plugin-commit-rules@0.1.0            ok
```

### `fxdevkit doctor`

一次自检，任何一项未通过时相关增强不会发生，并以退出码 `1` 退出。

```bash
$ fxdevkit doctor
[fxdevkit] Node                v22.22.2                                          ok
[fxdevkit] Git                 git version 2.55.0.windows.3                      ok
[fxdevkit] 仓库                D:/products/devkit                                ok
[fxdevkit] hooks 托管          D:\Users\yin.huang\.fxdevkit\hooks                  ok
[fxdevkit] 入口有效            D:\products\devkit\packages\cli\dist\index.js     ok
[fxdevkit] 插件 plugin-commit-rules   加载成功                                          ok
[fxdevkit] 全部检查通过，增强链路正常
```

### `fxdevkit install` / `fxdevkit uninstall`（机器级）

**一次安装，所有仓库默认增强。** `install` 把 `core.hooksPath` 写到 git 全局配置，指向 `~/.fxdevkit/hooks`；
之后所有仓库——包括以后新建和克隆的——都会走 fxdevkit 的 dispatcher，并被插件增强。
`uninstall` 是它的逆操作：清掉全局 `core.hooksPath` 并删除 dispatcher 脚本。

```bash
$ fxdevkit install
[fxdevkit] 全局 hooks 已挂载：D://Users//yin.huang//.fxdevkit//hooks
[fxdevkit] 已托管：commit-msg, prepare-commit-msg, post-checkout, post-merge, pre-commit, pre-push
[fxdevkit] 所有仓库（含以后新建的）现在都会被插件增强
[fxdevkit] 想排除某个目录 → 在该目录下执行 fxdevkit disable

$ fxdevkit uninstall
[fxdevkit] 已卸载全局 hooks，所有仓库均不再被增强
[fxdevkit] 用户配置未改动，exclude 列表保留
```

> 这两个命令各自只有一种行为：它们本来就是机器级的，不需要 `--global` 之类的修饰。
> 卸载 fxdevkit 时**不会**清除用户配置——配置属于人，卸载工具不该动它。

### `fxdevkit disable` / `fxdevkit enable`（范围）

控制「**这个目录**要不要被增强」。默认全都增强，只有被排除的目录例外。

- `disable`：把当前目录（在 git 仓库内即仓库根）写进用户配置 `~/.fxdevkit/config.yaml` 的 `exclude`；
- `enable`：把它从 `exclude` 中移除。

命中范围是**该目录及其所有子目录**。

```bash
$ cd D:/projects/legacy
$ fxdevkit disable
[fxdevkit] 已停用增强：D:/projects/legacy（含其所有子目录）
[fxdevkit] exclude 共 1 条 · D://Users//yin.huang//.fxdevkit//config.yaml

$ fxdevkit enable
[fxdevkit] 已恢复增强：D:/projects/legacy
[fxdevkit] exclude 共 0 条 · D://Users//yin.huang//.fxdevkit//config.yaml
```

也可以直接手改这个文件：

```yaml
# ~/.fxdevkit/config.yaml
exclude:
  - D:/projects/legacy
  - ~/tmp
```

**为什么存在用户配置而不是仓库里**：写进仓库的 `.git/config` 虽然也能用，但它不入版本控制——
重新 clone、换机器，停用状态就没了；放在用户配置里则跟人走，且能一处看全。

> **安全边界**：驱动器根目录（`C:/`）和用户主目录不允许写入，执行时会直接报错退出。
> 目录收窄的另一条路是插件级的 `projects` 白名单（见下文「插件作用目录」）；
> **`exclude` 黑名单优先于 `projects` 白名单**——黑名单命中即跳过，不再看白名单。

**disable / enable 只停自动触发，不停手动命令。** `git commit` 走的 hook 路径会尊重
exclude / `projects` / `plugin disable`；但你显式敲的 `fxdevkit <name> <cmd>`（如
`fxdevkit commit check`）**不受这些限制，照常执行**——命令是你亲手敲的意图，
工具不该拦你。想让一个插件彻底不可调，用 `fxdevkit plugin remove`。

### 分层执行：不取缔仓库自有 hooks

git 的 `core.hooksPath` 是**替换**语义——指向 fxdevkit 后，仓库自己 `.git/hooks/<name>`
  
原本就不会再被执行。fxdevkit 主动补上这一层，保证「仓库自有优先、fxdevkit 追加」：

| 层级      | 位置                         | 行为                            |
| ------- | -------------------------- | ----------------------------- |
| 仓库自有（优先） | `<repo>/.git/hooks/<name>` | 先执行；返回非零 → 按 git 原生语义**阻断提交** |
| fxdevkit（追加） | `~/.fxdevkit/hooks/<name>` | 再执行插件增强；只有插件显式 `reject` 才阻断   |

也就是说，仓库里原本装了 husky / lefthook / 自定义 hook 的，**照常执行，不会被取缔**。
  
仓库自有 hook 压根执行不起来（比如解释器缺失）时按放行处理，绝不会卡住你的提交。

### `fxdevkit update [version]`

更新 / 回退 fxdevkit 自身（通过 `npm` 全局安装的 `@fxdevkit/cli`）。

```bash
fxdevkit update              # 更新到 @fxdevkit/cli@latest
fxdevkit update 1.0.0        # 回退到指定版本
```

**卸载 fxdevkit 自身**：直接 `npm uninstall -g @fxdevkit/cli`，无需先卸载 hooks。残留的全局 hooks 会在入口失效时静默放行，不影响后续 git 操作。

## 四、插件命令

插件通过短名（`name`）路由，命令形式为 `fxdevkit <插件name> <命令>`。
  
CLI 源码不硬编码任何插件 id。

### 查看插件版本

```bash
$ fxdevkit commit -v
plugin-commit-rules@0.1.0
  name:    commit
  dir:     D:\products\devkit\node_modules\@fxdevkit\plugin-commit-rules
  命令:    check
```

### 查看插件帮助

```bash
$ fxdevkit commit --help
fxdevkit commit — plugin-commit-rules@0.1.0

用法:
  fxdevkit commit check
```

### 执行插件命令

```bash
fxdevkit commit check          # 触发 plugin-commit-rules 插件的 check 命令
```

> 插件未提供某命令时会提示，不会静默通过。

## 六、配置与事件

```bash
fxdevkit config show       # 打印合并后的生效配置
fxdevkit config validate   # 校验各插件配置
fxdevkit report            # 统计本地事件
fxdevkit trace             # 回溯增强何时生效 / 被跳过 / 开关变更
```

### 增强回溯（trace）

回答一个问题：**增强到底生效过没有，什么时候停的，为什么停的。**
典型场景是「AI 前缀怎么没了」——不是去看日志猜，而是直接看最后一次生效的时间：

```bash
$ fxdevkit trace
[fxdevkit] 增强回溯
[fxdevkit] 增强状态：最近一次 2026-09-02 18:00（15 天前）· plugin-commit-rules · commit-msg
[fxdevkit] → 已 15 天没有增强记录，见下方「最近变更」与「跳过原因分布」
[fxdevkit] 最近跳过：2026-09-07 19:02（10 天前）· 原因 out-of-scope
[fxdevkit] 最近变更：2026-09-05 19:00（12 天前）· scope.disabled · D:/projects

[fxdevkit] 跳过原因分布
     2  excluded
     1  out-of-scope
```

| 参数               | 说明                          |
| ---------------- | --------------------------- |
| `--repo <path>`  | 只包含某个仓库的记录（路径大小写、斜杠方向不敏感） |
| `--last <n>`     | 时间线显示最近 n 条，默认 20          |

跳过原因取值固定：`excluded`（目录被停用）、`invalid`（清单不合规）、`disabled`（插件被停用）、`out-of-scope`（不在插件 projects 内）、`load-failed`、`config-invalid`、`timeout`、`error`。

**只有插件 hook 真正跑完才算「增强生效」**，被上面任何一关拦下都记为跳过——否则会得出「昨天还在生效」的假象。

边界：hooks 未挂载期间 git 根本不会调用 fxdevkit，那段时间本地零记录，`trace` 补不出来，只能看到「最后一次生效停在 X 天前」。判断是否挂载用 `fxdevkit doctor`。

> 事件落盘受 `telemetry.enabled` 控制。关掉遥测后 trace / report 都不会再有新数据。

配置按层合并（源码默认 → 用户覆盖 → env），**用户配置覆盖源码默认**。

```bash
$ fxdevkit config show
{
  "layers": [
    { "name": "user", "path": "D:\\Users\\yin.huang\\.fxdevkit\\config.yaml", "applied": false },
    { "name": "env",  "applied": true }
  ],
  "config": { ... }
}
```

### 插件作用目录（projects）

每个插件可以声明「只在哪些目录下生效」。写在 `~/.fxdevkit/config.yaml`：

```yaml
plugins:
  plugin-commit-rules:
    enabled: true
    # 不写 projects → 全局生效：所有已启用的仓库都加载
  api-sync:
    enabled: true
    projects:
      - D:/products/order-service      # 只在该目录及其子目录下的仓库生效
```

规则：

| 配置                  | 效果                                |
| ------------------- | --------------------------------- |
| 不写 `projects`（或空数组） | **全局生效**，所有已启用 fxdevkit 的仓库都加载该插件 |
| 写了 `projects`       | 只有仓库根目录位于其中某目录**或其子目录**下才加载       |

判定由内核完成，插件自身不感知。`fxdevkit status` 会显示每个插件是否命中：

```bash
$ fxdevkit status
[fxdevkit] 插件:
  commit        plugin-commit-rules@0.1.0            未生效
      → 当前仓库不在作用目录内（已配：D:/products/order-service）
```

> 不在作用目录内是**配置预期**，不是故障——`doctor` 对此判定为通过。

### 日志追踪（logs）

内核与插件各有一条日志通道，均落盘到 `~/.fxdevkit/logs/YYYY-MM-DD.log`（结构化 JSON）：

| 通道       | 内容                                       |
| -------- | ---------------------------------------- |
| `core`   | 内核调度日志：派发哪个 hook、候选插件几个、逐个执行与结果、跳过/超时/兜底 |
| `plugin` | 某个插件的执行日志（插件通过 `ctx.logger` 打出）          |

```bash
fxdevkit logs                       # 今天的全部日志（core + plugin）
fxdevkit logs --core                # 只看内核调度日志
fxdevkit logs --plugin plugin-commit-rules # 只看某个插件的执行日志
fxdevkit logs --level error         # 只看 error 及以上（debug|info|warn|error）
fxdevkit logs --day 2026-09-07      # 查看指定日期
fxdevkit logs --days                # 列出有哪些日期的日志文件
fxdevkit logs --last 20             # 只看最后 20 条
```

输出示例：

```
10:50:17  core   info   派发 commit-msg · 仓库 D:/products/devkit
10:50:17  core   info   声明 commit-msg 的候选插件 1 个
10:50:17  core   info   [plugin-commit-rules] 执行 commit-msg
10:50:17  core   info   [plugin-commit-rules] 完成：modify
```

打印策略：`warn` / `error` 恒打到 stderr；`info` / `debug` 默认只落盘不打印（避免每次提交刷屏），
  
设置 `FXDEVKIT_DEBUG=1` 后完整打印。`FXDEVKIT_LOG=0` 可关闭落盘。

## 八、目录结构

fxdevkit 的用户级目录默认在 `~/.fxdevkit`（可用 `FXDEVKIT_HOME` 覆盖）：

```
~/.fxdevkit/
├── config.yaml      # 用户自定义配置（覆盖源码默认）
├── hooks/           # 分发的 git hook 脚本
├── plugins/         # 插件安装目录（npm 包）
├── events/          # 事件落盘记录
├── cache/           # 缓存
└── package.json     # 插件依赖清单
```

> 配置只有两层：**源码默认**（在 `@fxdevkit/cli` 包内，不可改）+ **用户覆盖**（`~/.fxdevkit/config.yaml`）。工程目录零侵入——fxdevkit 不会在仓库根目录写任何 `.fxdevkit.yaml`。

## 九、常见问题

- **`doctor` 有一项失败**：相关增强不会发生。常见如全局 hooks 未安装 → 执行 `fxdevkit install`。
- **某个目录不想被增强**：在该目录内执行 `fxdevkit disable`（写进用户配置的 `exclude`）。
- **插件未加载**：执行 `fxdevkit plugin list` 查看是否被 `SKIPPED`，以及 `fxdevkit config validate` 校验配置。
- **卸载 / 更新 fxdevkit 自身**：更新见 `fxdevkit update`；卸载直接 `npm uninstall -g @fxdevkit/cli`。


### Cursor 里用 GUI 提交，hook 不生效

**现象**：在 Cursor 左侧 Source Control 面板点提交，commit message 没加 `AI ` 前缀、hook 日志也没新增；但在 Cursor 内置终端里敲 `git commit` 却正常。

**根因**：Cursor 3.15.6+ 的 git 扩展在每次调用 git 时，通过环境变量强制注入 `core.hooksPath=/dev/null`（Windows 上是 `NUL`），导致所有 git hooks 被静默跳过。这是 Cursor 官方已确认的 bug，不是 fxdevkit 的问题。命令行提交正常，是因为该覆盖只存在于 Cursor 自己 spawn git 的环境里，终端不受影响。

**解法（不降级）**：给 Cursor 配一个 git wrapper，把这条覆盖洗掉。wrapper 已打包成单文件 exe `scripts/git-hooks-restore.exe`，配置如下（写入 Cursor 的 `settings.json`）：

```json
"git.path": "D:\\products\\devkit\\scripts\\git-hooks-restore.exe"
```

> 必须用 **string 形式**（exe 路径），不能用 `["node.exe", "wrapper.cjs"]` 这种 array 形式——
>   
> Cursor 3.19 对 array 形式的支持有问题，会把 git 集成一并搞挂。

然后**完全退出并重启 Cursor**（不是 reload window）。wrapper 会删掉 `core.hooksPath` 的覆盖、把命令原样转发给真正的 git，其余环境变量（含凭证、`VSCODE_GIT_COMMAND` 等）全部保留。真正 git 的位置可用环境变量 `FXDEVKIT_REAL_GIT` 覆盖（默认 `D:\softs\Git\bin\git.exe`）。

**wrapper 的日志**：默认**只记异常**（找不到 git、spawn 失败），落 `~/.fxdevkit/logs/wrapper.log`。要看每次转发的细节（比如验证 `core.hooksPath` 有没有被洗掉），建一个空文件 `~/.fxdevkit/wrapper-debug` 即开启，删掉即关闭 —— 不用重启 Cursor，下次 git 调用就生效。排查完把 `wrapper.log` 删掉即可，它不需要持久化。

> 改 `scripts/git-hooks-restore.cjs` 之后必须**重新打包 exe**（Cursor 跑的是 exe，不是源码）：
> `npx pkg@5.8.1 git-hooks-restore.cjs --target node18-win-x64 --output <exe 路径>`。
> 打包前先把旧 exe 改名让位 —— pkg 会先 unlink 目标文件，目标存在且被占用时会 EPERM。

**前置条件**：必须用 **multi-root workspace** 打开多个仓库，而不是直接打开父目录 `D:\projects`（父目录本身不是 git 仓库，Cursor 会显示「没有 Git 存储库」）。已有现成的 `D:\projects\projects.code-workspace`。

**回滚**：删掉 `settings.json` 里的 `git.path` 即可。

**代价**：每次 git 调用会多一层 Node 进程，Source Control 面板刷新可能略慢（毫秒级），这是「GUI 提交也能跑 hooks」的取舍。若 Cursor 官方后续修复，删掉 `git.path` 即可回到原生行为。
